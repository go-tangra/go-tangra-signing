# signing join bundle

Generated by the gateway (Gateway operations › Modules › signing › Add).

    docker compose up -d

`private/` holds credentials (the single-use enrolment token, the bundle's
TLS keys); `.env` holds generated passwords and the module key-encryption
key (`GEN_KEY_1`, it seals the tenant signing CAs). Keep both on this host
only and back up `.env` together with the `signing-db` and `signing-s3`
volumes. The enrolment token is valid for the lifetime chosen in the wizard;
after the first start the module renews its identity itself.

The bundle runs signing with its own TimescaleDB and object store. On the
core, before the first start (see ../README.md, "Mesh policies"):

- the core Valkey accepts TLS from this host for the ACL user `signing`;
- the auth, notification, warden and scheduler policies admit
  `svc/signing`, and the scheduler's `discovery.static.signing` is
  `<advertise host>:9915` (expiry and reminders);
- for qualified signing, the portal edge `connect_sources` allows BISS.
